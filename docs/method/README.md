## 예측 기준일, horizon, 입력

예측 기준일 `t`는 **그날 영업이 끝나 판매량과 거래량을 확인한 시점**입니다. `forecast_horizon=h`는 목표일이 `t+h`라는 뜻이며 `h=1~7`입니다. 예를 들어 `t=7월 19일`, `h=3`이면 7월 22일 판매량을 예측합니다. `lag 7`은 기준일보다 7일 전인 7월 12일의 판매량입니다. 목표일인 7월 22일의 판매량은 정답이며 입력이 아닙니다.

| 방식 | 한 번의 입력 | 출력 | 여러 매장을 배우는 방식 |
|---|---|---|---|
| LightGBM·CatBoost | 기준일의 표형 Feature와 `forecast_horizon`; 기준일마다 7개 행 | 각 행의 미래 일별 판매량 | 매장·상품군을 함께 학습하는 전역 모델 |
| N-HiTS·TCN·TFT | 매장·상품군의 과거 56일 판매 시계열과 미리 아는 요일·월 | 향후 7일을 한 번에 출력 | 여러 매장·상품군 시계열의 학습 창으로 전역 학습 |

56일 입력은 **56일 모두 판매가 0보다 커야 한다는 조건이 아닙니다.** 관측된 0 판매와 원본에서 날짜 자체가 빠진 경우는 별도로 표시합니다. DL은 ML보다 외부 Feature가 적어 비교 결과가 순수한 구조 차이만 나타내지는 않습니다.

## Baseline과 Feature 선정

[EDA](../../notebooks/01_eda.ipynb)의 주간 반복 관찰을 바탕으로 목표일 `d=t+h`의 **전주 동일 요일 `d-7`** 판매량과 **최근 4주 동일 요일 `d-7, d-14, d-21, d-28` 평균**을 Baseline으로 둡니다. `h<=7`이므로 가장 최근의 참조일 `d-7`도 기준일 `t`보다 늦지 않습니다. 이는 복잡한 모델이 단순한 주간 규칙보다 실제로 나은지 묻는 기준입니다.

| ML Feature 그룹 | 현재 설정 | 기준일에 사용 가능한 이유 |
|---|---|---|
| 최근 판매 | 기준일 판매량과 lag 1·7·14·28·56 | 모두 `t` 또는 이전 날짜의 관측값 |
| 수요 수준 | 7·14·28일 이동평균 | 최소 하루 이전부터 계산해 이동평균의 미래 유입 방지 |
| 같은 요일 패턴 | 목표일과 같은 요일의 이전 주·4주 평균 | 참조일이 `t`를 넘지 않음 |
| 달력·매장 | 목표일 요일·월, 매장·상품군 특성, 휴일 표시 | 달력은 사전에 확인할 수 있다는 운영 가정 |
| 기준일 거래 | 기준일 거래량 | 영업 종료 후 예측한다는 운영 가정 |

유가는 일별 매장·상품군 수요와의 설명 가능성이 낮아 제외했습니다. 원본의 **목표일 판촉 수량 `target_onpromotion`은 제외**했습니다. 이는 사전 판촉 계획이 아니라 목표일에 기록된 값이므로 7일 전 예측 시 알 수 있다고 가정하지 않습니다. 미래 돌발 행사·지진 표시도 현재 비교 입력에서 제외합니다. 휴일의 이전·대체 여부처럼 사후에 바뀔 수 있는 정보는 실제 운영 시점에 알 수 있었는지 추가 확인이 필요합니다. [Feature 노트북](../../notebooks/04_feature_engineering.ipynb)에 변수별 생성 과정을 둡니다.

## 모델을 선택한 이유와 기본 원리

| 모델 | 계열·원리 | 이 프로젝트에서 확인할 점 |
|---|---|---|
| LightGBM | 이전 나무들이 줄이지 못한 손실을 다음 나무가 단계적으로 줄이는 Gradient Boosting | 다양한 표형 Feature의 강한 기준 |
| CatBoost | 범주형 입력을 다루는 Gradient Boosting | 매장·상품군 정보가 많은 표형 문제에서의 비교 |
| N-HiTS | 입력 구간을 여러 시간 규모로 요약하는 MLP 계열 | 장·단기 패턴의 직접적인 다중 일 예측 |
| TCN | 과거 방향의 합성곱으로 시간 패턴을 읽는 CNN 계열 | 반복되는 국소 패턴의 활용 |
| TFT | 순환 계층과 attention을 함께 사용하는 모델 | 시간에 따라 중요한 입력을 달리 활용하는 방식 |

다섯 모델을 모두 유지하되, **성능만으로 딥러닝의 우월성을 가정하지 않습니다.** LightGBM과 CatBoost는 전체 이력 Feature를 쓰고, DL 세 모델은 NeuralForecast의 연속 시계열 입력을 사용합니다. 별도의 Transformer 모델을 추가하거나 직접 PyTorch 모델을 새로 구현하는 일은 현재 비교 범위에 넣지 않았습니다.

ML의 전체 이력 실험은 LightGBM `regression`(제곱오차 계열), CatBoost `RMSE` 목적함수를 사용합니다. DL 세 모델은 MSE로 학습하며, 내부 검증 MSE는 학습 상태를 보는 값입니다. **학습 손실과 최종 보고 지표는 구분**하고, 최종 성능은 동일한 예측 행의 MAE·RMSE·RMSLE·WAPE·Bias로 확인합니다.

## 시계열 분할과 누수 방지

| 역할 | 기준일 | 모델 가중치·정답 사용 |
|---|---|---|
| Train | Valid보다 이전 | 목표 판매일이 2017-07-18까지인 행만 학습 |
| Valid | 2017-07-19~25 | ML 조기 종료와 DL 설정 선택; 정답으로 가중치 재학습하지 않음 |
| 간격 | 2017-07-26~08-01 | 평가 기준일로 사용하지 않음 |
| Test | 2017-08-02~08 | 선택한 모델을 고정하고 최종 비교 |

Valid의 마지막 기준일인 7월 25일에서 `h=7`의 정답은 **8월 1일**입니다. 다음 날인 8월 2일부터 Test 기준일을 잡으면 Valid 결과를 확인한 뒤 Test가 시작되는 순서가 됩니다. 간격은 모든 관측을 버린다는 뜻이 아닙니다. 각 예측 기준일에 이미 관측된 판매량은 그 시점의 입력 이력으로 사용할 수 있지만, **모델 가중치는 Test 전에 다시 학습하지 않습니다.**

ML은 Valid로 학습을 멈출 나무 수를 고른 뒤 **같은 모델**로 Test를 예측합니다. DL은 7월 18일까지의 학습 정답으로 가중치를 갱신하고, 내부 7일 검증 MSE를 모니터링합니다. 별도 외부 Valid는 7개 기준일 각각에서 1~7일을 예측하며, 저장한 동일 모델로 Test를 예측합니다. 두 계열은 Valid·Test의 매장·상품군·기준일·horizon·정답을 맞춥니다. 검증과 테스트에서 7일 × 7개 horizon의 정답이 모두 있는 시계열만 공통 집합에 포함합니다. **판매량이 0인 날은 결측일이 아닙니다.**

기준일별 lag·이동평균 및 DL 입력은 그날까지의 관측값만 읽습니다. 목표값은 날짜·매장·상품군 키로 결합해 누락 날짜 때문에 행이 밀리는 문제를 피합니다. 무작위 Train/Test 분할은 사용하지 않습니다. 다만 현재 Test 주간은 이전 실험에서 이미 여러 차례 확인되어, 완전히 독립적인 최초 평가라고 부르지 않습니다.
